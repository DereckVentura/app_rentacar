# Acta técnica de entrega de AutoRent

Fecha: 29 de octubre de 2026. Modalidad: demostración universitaria local para el caso Rent a Car Molina. Universidad, docente y equipo de integrantes: completar por el solicitante.

## Archivos y funciones entregadas

Aplicación Flutter web y Android; API Express TypeScript; esquema MySQL y migraciones; catálogo de tres vehículos; cuentas y permisos; cotizaciones, reservas e historial; cancelación, entrega y devolución; kilometraje y ubicaciones; avisos privados; administración de flota, fotos y preguntas frecuentes; documentos académicos con aceptación versionada; exportación propia y solicitudes de derechos o reclamos.

El informe Word y PDF de 24 páginas incluye problema, objetivos, alcance, requisitos, método, arquitectura, modelo de datos, integridad, pruebas, instalación, alojamiento, limitaciones, referencias y anexos. Se acompañan manuales, diccionario de 15 tablas, diagramas editables, guion de defensa y código empaquetado con comprobaciones de integridad.

## Comprobaciones realizadas

TypeScript typecheck y build correctos. Backend: 93 pruebas aprobadas. Operaciones: 29 comprobaciones MySQL HTTP aprobadas. Privacidad: 18 comprobaciones MySQL HTTP aprobadas. Flutter: análisis sin observaciones y cinco pruebas aprobadas. Web compilada con motor y fuentes incluidos; navegador revisado en móvil y escritorio, con acceso administrativo y formulario de flota. Android debug compilado, instalado y abierto en AutoRent_API_36; catálogo comprobado visualmente.

El informe se exportó con Microsoft Word instalado y se revisó mediante imágenes de todas sus páginas. El código anterior se respaldó al actualizar la carpeta del proyecto. La configuración privada de la base existente se conserva. Las credenciales de la demostración se generan localmente y no se publican en los paquetes.

## Pendientes de información y operación real

Tarifas, kilometrajes, placas, ubicaciones reales y versiones exactas no proporcionados permanecen pendientes. La flota inicial no acepta reservas hasta completar sus datos; las pruebas de reserva utilizan datos ficticios en su entorno aislado. No hay pagos ni recogida de documentos de identidad, GPS de clientes o facturación electrónica.

La demostración utiliza una base independiente y accesos propios. La base existente aún requiere la contraseña administrativa introducida localmente para agregar las tablas nuevas. La publicación pública requiere cuentas del titular en proveedores y una dirección HTTPS verificada. La comercialización necesita el trabajo descrito en la guía específica, incluida verificación de correo y recuperación de contraseña, condiciones comerciales, derechos, procedimientos y revisión profesional.
